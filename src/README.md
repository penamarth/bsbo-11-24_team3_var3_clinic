# ИС «ПолиКлик»: прототип на C#

Консольная программа показывает запись пациента и ведение приема на готовом сценарии. Данные хранятся в памяти и исчезают после выхода.

## Запуск

Нужен .NET SDK 10:

```bash
dotnet build src/PoliClick.sln
dotnet run --project src/PoliClick
dotnet run --project src/PoliClick.Checks
```

Внешних NuGet-пакетов нет. Проверки запускаются отдельной консольной программой `PoliClick.Checks`.

## Демонстрация

1. Создает врача, двух пациентов и слоты на два дня в разных кабинетах.
2. Показывает свободное время и записывает пациента.
3. Отклоняет попытку другого пациента занять тот же слот.
4. Открывает прием один раз и заполняет полученный объект `Appointment`.
5. Завершает прием и отклоняет попытку изменить его данные.
6. Проводит второй прием и показывает оба результата в истории пациента.

Время сценария меняется программно (см. `Program.cs`), поэтому ждать наступления слота не нужно.

## Классы

- `Clinic` хранит пациентов и врачей, создает расписание, оформляет и отменяет записи. `OpenAppointment` открывает существующую запись для назначенного врача. `StartAppointment` проверяет условия начала, начинает прием и возвращает тот же объект.
- `SlotStorage` хранит только `TimeSlot`, нарезает рабочий интервал на слоты и ищет свободное время. // `WorkShift` не создается.
- `TimeSlot` хранит время, врача, номер кабинета и запись, которая занимает слот. Свободный слот можно найти еще до появления пациента.
- `Appointment` хранит пациента, врача, кабинет, слот и данные конкретного приема: жалобы, анамнез, осмотр, диагноз, назначения и фактическое время начала и окончания. Врач и кабинет копируются из слота при записи и доступны только для чтения.
- `Patient` хранит номер полиса, признак прикрепления и список записей. Медицинская история состоит из завершенных приемов `Appointment`, каждый со своими данными.
- `Doctor` содержит ФИО, специальность и длительность слота. Для врачей одной специальности длительность одинакова.

`AppointmentStatus`: `PLANNED` → `IN_PROGRESS` → `COMPLETED`. Запланированную запись можно отменить (`CANCELLED`): она останется у пациента, а слот освободится. После завершения приема слот остается использованным.

Текущий прием остается в локальной переменной:

```csharp
var appointment = clinic.StartAppointment(doctor.Id, appointmentId);
appointment.SetExamination(complaints, anamnesis, examination);
appointment.SetDiagnosis(code);
appointment.AddPrescription(prescription);
appointment.Complete();
```

## Проверки и ограничения

При создании расписания проверяется, свободны ли врач и кабинет. Для записи нужны свободный слот, прикрепление пациента и отсутствие другой активной записи к той же специальности. Записаться можно на 14 дней вперед, отменить запись самостоятельно можно не позднее чем за час до приема. Для завершения приема нужны обязательные данные.

Начать прием можно только в назначенный день, в том числе раньше времени слота. У врача и пациента не должно быть другого идущего приема, а кабинет должен быть свободен. Эти проверки выполняет `StartAppointment`; после начала врач заполняет полученный `Appointment` локально.

Во время бронирования общая блокировка `Clinic` защищает проверку слота и активных записей пациента. Она работает внутри одного процесса; базы данных пока нет.

Используется местное время поликлиники, без обработки часовых поясов. Код диагноза проверяется по формату, но самого справочника МКБ-10 пока нет. В первом варианте у приема один диагноз.

`Complete()` фиксирует данные и запрещает их менять. Настоящей УКЭП, исправлений подписанных документов и передачи СЭМД пока нет. Завершение приема в прототипе не является электронной подписью.

При открытии приема проверяется, принадлежит ли `doctorId` назначенному врачу. Входа пользователей и полноценной проверки доступа пока нет. Все данные в демонстрации учебные.

Перенос записи, направления, лист ожидания, историю прикреплений, автоматическую очередь, внешние сервисы и Адаптер добавим в следующих итерациях. UML-документы пока описывают предыдущую модель.
