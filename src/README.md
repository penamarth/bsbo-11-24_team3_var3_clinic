# ИС «ПолиКлик»: прототип на C#

Консольная программа показывает запись пациента, ведение приема и автоматическую очередь на готовых сценариях. Данные хранятся в памяти и исчезают после выхода.

## Запуск

Нужен .NET SDK 10:

```bash
dotnet build src/PoliClick.sln
dotnet run --project src/PoliClick
dotnet run --project src/PoliClick -- --queue-demo
```

Внешних NuGet-пакетов нет.

## Демонстрация записи и приема

1. Создает врачей двух специальностей, двух пациентов и слоты на три дня в разных кабинетах.
2. Показывает специальности и выбирает одну из них.
3. Показывает оба способа поиска: по дате среди всех врачей специальности и по ФИО выбранного врача. В обоих случаях сначала выбирается день, затем время.
4. Выбирает слот, подтверждает запись и отклоняет попытку другого пациента занять то же время.
5. Начинает прием, заполняет и завершает его. Отклоняет попытку изменить завершенный прием.
6. Проводит второй прием и показывает оба результата в истории пациента.

Время сценария меняется программно (см. `Program.cs`), поэтому ждать наступления слота не нужно.

## Демонстрация очереди

Режим `--queue-demo` показывает три кабинета на двух табло. Программа обновляет очередь по таймеру раз в секунду. Одна секунда демонстрации соответствует пяти минутам расписания; начало и завершение приемов, а также отметка неявки заданы сценарием в `QueueDemo.cs`.

Очередь сама выбирает запись на сегодня с самым ранним наступившим временем. Учитывает занятость врача, пациента и кабинета. Пока вызванный пациент не начал прием, следующий вызов на те же ресурсы не отправляется. Повторное обновление сохраняет ожидающий вызов без нового сигнала.

Врач начинает и завершает прием обычными действиями. На ближайшем обновлении очередь учитывает новое состояние и вызывает следующего пациента, если его время уже наступило. При задержке приема вызов откладывается.

Неявку подтверждает назначенный врач через `MarkNoShow`, не раньше чем через 15 минут после начала слота. Таймер сам не объявляет неявку. Такая запись остается в истории записей, но не входит в медицинскую историю завершенных приемов, а слот остается использованным.

Кабинет должен относиться к зарегистрированному табло. Одно табло обслуживает группу кабинетов, кабинет относится только к одному табло. На табло выводятся текущие вызовы: номер записи и номер кабинета, без ФИО. При начале приема или отметке неявки вызов снимается на ближайшем обновлении. В демонстрации звуковой сигнал обозначен текстом `[сигнал]`.

## Классы

- `Clinic` создает хранилища пациентов, врачей и слотов, оформляет и отменяет записи, создает расписание. Для начального выбора возвращает специальности, врачей и дни со свободным временем. `OpenAppointment` открывает существующую запись для назначенного врача. `StartAppointment` проверяет условия начала, начинает прием и возвращает тот же объект. `UpdateQueue` автоматически выбирает следующие записи для вызова, `MarkNoShow` сохраняет подтвержденную врачом неявку.
- `QueueBoard` хранит идентификатор табло, группу кабинетов и текущие вызовы. В вызове есть только номер записи и кабинет.
- `PatientStorage` хранит пациентов, добавляет их и находит по идентификатору. Не допускает повторного добавления одного полиса.
- `DoctorStorage` хранит врачей, добавляет их и находит по идентификатору. Возвращает специальности без повторов и врачей выбранной специальности по ФИО. Проверяет единую длительность слота для специальности.
- `SlotStorage` хранит только `TimeSlot`, нарезает рабочий интервал на слоты, ищет доступные дни и свободное время. // `WorkShift` не создается.
- `TimeSlot` хранит время, врача, номер кабинета и запись, которая занимает слот. Свободный слот можно найти еще до появления пациента.
- `Appointment` хранит пациента, врача, кабинет, слот и данные конкретного приема: жалобы, анамнез, осмотр, диагноз, назначения и фактическое время начала и окончания. `CalledAt` хранит время вызова пациента. Врач и кабинет копируются из слота при записи и доступны только для чтения.
- `Patient` хранит номер полиса, признак прикрепления и список записей. Медицинская история состоит из завершенных приемов `Appointment`, каждый со своими данными.
- `Doctor` содержит ФИО, специальность и длительность слота. Для врачей одной специальности длительность одинакова.

`AppointmentStatus`: `PLANNED` → `IN_PROGRESS` → `COMPLETED`. Запланированную запись можно отменить (`CANCELLED`): она останется у пациента, а слот освободится. После завершения приема слот остается использованным. При подтвержденной неявке запись получает статус `NO_SHOW`; фактический прием не начинается, слот также остается использованным.

Текущий прием остается в локальной переменной:

```csharp
var appointment = clinic.StartAppointment(doctor.Id, appointmentId);
appointment.SetExamination(complaints, anamnesis, examination);
appointment.SetDiagnosis(code);
appointment.AddPrescription(prescription);
appointment.Complete();
```

## Проверки и ограничения

При создании расписания проверяется, свободны ли врач и кабинет. Для записи нужны свободный слот, прикрепление пациента и отсутствие другой активной записи к той же специальности. Записаться можно на 14 дней вперед, отменить запись самостоятельно можно не позднее чем за час до приема. Для завершения приема нужны обязательные данные.

Начать прием можно только в назначенный день, в том числе раньше времени слота. У врача и пациента не должно быть другого идущего приема или ожидающего вызова, а кабинет должен быть свободен. Ожидающий вызов самой открываемой записи началу приема не мешает. Эти проверки выполняет `StartAppointment`; после начала врач заполняет полученный `Appointment` локально.

Во время бронирования общая блокировка `Clinic` защищает проверку слота и активных записей пациента. Она работает внутри одного процесса; базы данных пока нет.

Используется местное время поликлиники, без обработки часовых поясов. Код диагноза проверяется по формату, но самого справочника МКБ-10 пока нет. В первом варианте у приема один диагноз.

`Complete()` фиксирует данные и запрещает их менять. Настоящей УКЭП, исправлений подписанных документов и передачи СЭМД пока нет. Завершение приема в прототипе не является электронной подписью.

При открытии приема проверяется, принадлежит ли `doctorId` назначенному врачу. Входа пользователей и полноценной проверки доступа пока нет. Все данные в демонстрации учебные.

Перенос записи, направления, лист ожидания, история прикреплений, внешние сервисы и Адаптер в прототипе не реализованы.
