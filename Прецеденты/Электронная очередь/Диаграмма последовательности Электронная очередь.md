# Диаграмма последовательности «Электронная очередь»

Реализованная часть прецедента [«Электронная очередь»](Электронная%20очередь.md): автоматический выбор записей для вызова, обновление табло, начало и завершение приема, отметка неявки врачом.

В `QueueDemo` программа вызывает `Clinic.UpdateQueue()` по таймеру. `Clinic` берет записи из своего списка `appointments`, время из `Appointment.Slot.Start`, врача и кабинет из самой записи. Табло выбирается по `QueueBoard.CabinetNumbers`. Действия врача происходят между обновлениями очереди; полученный при начале приема `Appointment` хранится локально.

![Рис. Электронная очередь 1. Автоматическая очередь и действия врача](../../img/queue-sequence.png)

```plantuml
@startuml queue-sequence
actor Врач
participant ":Clinic" as C
participant ":Appointment" as A
participant ":QueueBoard" as B

loop В часы приема
  group Автоматическое обновление очереди по таймеру
    [-> C ++ : UpdateQueue()
    loop Для каждого табло
      C -> B : Clear()
    end
    loop Вызванные сегодня пациенты, ожидающие начала приема
      C -> B : ShowCall(cabinetNumber, appointmentNumber)
    end
    loop Еще не вызванные записи PLANNED на сегодня,\nвремя которых наступило, по времени слотов
      opt Табло найдено; врач, пациент и кабинет свободны
        C -> A : Call(currentTime)
        C -> B : ShowCall(cabinetNumber, appointmentNumber)
      end
    end
    [<-- C -- : новые вызовы
  end

  opt Действие врача между обновлениями
    alt Пациент подошел
      Врач -> C ++ : StartAppointment(doctorId, appointmentId)
      C -> A : Start(currentTime)
      C --> Врач -- : appointment
    else Прием идет, обязательные данные заполнены
      Врач -> A ++ : Complete()
      A --> Врач -- : прием завершен
    else Пациент не пришел, от начала слота прошло не менее 15 минут
      Врач -> C ++ : MarkNoShow(doctorId, appointmentId)
      C -> A : MarkNoShow(currentTime)
      C --> Врач -- : неявка отмечена
    end
  end
end

@enduml
```

## Операции очереди

| Класс | Операция | Что делает |
| --- | --- | --- |
| `Clinic` | `UpdateQueue()` | Обновляет табло, сохраняет ожидающие вызовы, выбирает новые записи по времени с учетом занятости врача, пациента и кабинета. Возвращает только новые вызовы |
| `Appointment` | `Call(calledAt)` | Сохраняет время первого вызова в `CalledAt`. Запись остается `PLANNED` |
| `QueueBoard` | `Clear()` | Очищает текущие вызовы перед обновлением табло |
| `QueueBoard` | `ShowCall(cabinetNumber, appointmentNumber)` | Сохраняет номер записи для кабинета, который обслуживает табло |
| `Clinic` | `StartAppointment(doctorId, appointmentId)` | Проверяет условия начала приема, вызывает `Start(currentTime)` и возвращает существующий `Appointment` |
| `Appointment` | `Complete()` | Проверяет обязательные данные и завершает начатый прием со статусом `COMPLETED` |
| `Clinic` | `MarkNoShow(doctorId, appointmentId)` | Находит запись, проверяет назначенного врача и передает отметку неявки в `Appointment` |
| `Appointment` | `MarkNoShow(currentTime)` | Для записи `PLANNED` сохраняет статус `NO_SHOW`, если от начала слота прошло не менее 15 минут |

Ожидающий вызов на сегодня занимает врача, пациента и кабинет до начала приема или отметки неявки. При идущем приеме они также заняты. На следующем обновлении завершенный прием и неявка перестают блокировать очередь, а вызов снимается с табло. Повторное обновление сохраняет ожидающий вызов без нового сигнала.

В прототипе табло хранится в памяти: консоль читает `QueueBoard.Calls` и показывает номер записи и кабинет. Звуковой сигнал обозначен текстом `[сигнал]`. Просмотр списка врача, вызов выбранной записи, ручной повторный вызов и история последних вызовов описаны в прецеденте; на этой диаграмме показана реализованная часть.
