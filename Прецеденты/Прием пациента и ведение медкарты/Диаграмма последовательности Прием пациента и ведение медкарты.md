# Диаграмма последовательности «Прием пациента и ведение медкарты»

Основной успешный сценарий прецедента [«Прием пациента и ведение медкарты»](Прием%20пациента%20и%20ведение%20медкарты.md), шаги 1–9. Неявка, просмотр карты пациентом и остальные расширения описаны в тексте прецедента.

Врач работает на своем рабочем месте `:VisitUI`. Пациента, которому врач начинает прием, он берет из своего списка на день: этот список ведет прецедент «Электронная очередь». `:VisitService` открывается для вошедшего врача и хранит текущий визит между операциями. Поэтому после `startVisit` операции не передают идентификаторы. Запись на прием врач берет у `:Doctor`, где хранятся его слоты и записи на них. Записи ЭМК хранятся у пациента (`:Patient`).

```plantuml
@startuml visit-sequence
actor Врач
boundary ":VisitUI" as UI
participant ":VisitService" as S
participant ":Doctor" as D
participant ":Appointment" as A
participant ":Visit" as V
participant ":Patient" as P
participant ":MedicalRecord" as MR
participant ":Diagnosis" as Dg
participant ":Icd10Catalog" as ICD
participant ":EgiszService" as E

Врач -> UI : нажимает «Начать прием»\nнапротив пациента
UI -> S ++ : startVisit(appointmentId)
S -> D ++ : getAppointment(appointmentId)
D --> S -- : appointment
S -> A ++ : startVisit()
A -> V ** : create(appointment)
A --> S -- : visit
S -> A ++ : getPatient()
A --> S -- : patient
S -> P ++ : getSignedRecords()
P --> S -- : история приемов
S --> UI -- : ЭМК пациента (ПРАВ18)
UI --> Врач : данные пациента, полис,\nистория, аллергии

Врач -> UI : вводит жалобы, анамнез\nи данные осмотра
UI -> S ++ : enterExamination(complaints, anamnesis, examination)
S -> P ++ : createRecord(visit)
P -> MR ** : create(visit)
P --> S -- : record (черновик, ПРАВ24)
S -> MR ++ : setExamination(complaints, anamnesis, examination)
MR --> S --
S --> UI --

Врач -> UI : начинает вводить диагноз
UI -> S ++ : findIcd10(text)
S -> ICD ++ : find(text)
ICD --> S -- : подходящие коды
S --> UI -- : подсказка кодов МКБ-10 (ПРАВ16)
Врач -> UI : выбирает основной\nи сопутствующие диагнозы
loop для каждого диагноза
  UI -> S ++ : addDiagnosis(icd10Code, isMain)
  S -> MR ++ : addDiagnosis(icd10Code, isMain)
  MR -> Dg ** : create(icd10Code, isMain)
  MR --> S --
  S --> UI --
end

Врач -> UI : вводит назначения
UI -> S ++ : addPrescription(prescription)
S -> MR ++ : addPrescription(prescription)
MR --> S --
S --> UI --

Врач -> UI : подписывает запись УКЭП
UI -> S ++ : finishVisit(signature)
S -> MR ++ : isComplete()
MR --> S -- : да (ПРАВ23)
S -> MR ++ : sign(signature)
MR --> S -- : запись подписана (ПРАВ15)
S -> V ++ : finish()
V -> A ++ : complete()
A --> V -- : статус «состоялась»
V --> S --
S -> E ++ : sendSemd(record)
E --> S -- : СЭМД принят (ПРАВ19)
S --> UI -- : выписка, рецепт
UI --> Врач : печать выписки и рецепта\nили отправка в личный кабинет

@enduml
```

## Системные операции

| Шаг сценария | Операция | Что делает |
| --- | --- | --- |
| 1–2 | `startVisit(appointmentId)` | Находит запись на прием у врача, создает визит и возвращает ЭМК пациента: врач видит ее, потому что пациент записан к нему (ПРАВ18) |
| 4 | `enterExamination(complaints, anamnesis, examination)` | Создает в ЭМК черновик записи (ПРАВ24) и сохраняет в нем жалобы, анамнез и данные осмотра |
| 5 | `findIcd10(text)` | Подсказывает коды по справочнику МКБ-10 (ПРАВ16) |
| 5 | `addDiagnosis(icd10Code, isMain)` | Добавляет в запись основной или сопутствующий диагноз |
| 6 | `addPrescription(prescription)` | Добавляет в запись назначение. Направления выдаются в расширении «Выдача направления» |
| 7–9 | `finishVisit(signature)` | Проверяет обязательные поля (ПРАВ23), подписывает запись УКЭП врача (ПРАВ15), завершает визит, меняет статус записи на прием на «состоялась», передает СЭМД в ЕГИСЗ (ПРАВ19) и возвращает выписку и рецепт |
