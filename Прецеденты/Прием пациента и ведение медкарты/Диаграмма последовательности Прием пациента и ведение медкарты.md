# Диаграмма последовательности «Прием пациента и ведение медкарты»

Реализованная часть прецедента [«Прием пациента и ведение медкарты»](Прием%20пациента%20и%20ведение%20медкарты.md): начало приема с проверками и отказами, просмотр истории, заполнение и завершение приема в памяти.

Врач один раз вызывает `Clinic.StartAppointment` и получает существующий `Appointment`, созданный при записи пациента. Дальше текущий прием хранится локально. Его методы заполняют данные без повторного поиска через `Clinic`. История берется у пациента этого приема (`appointment.Patient`).

![Рис. Прием пациента 1. Диаграмма последовательности приема](../../img/visit-sequence.png)

```plantuml
@startuml visit-sequence
actor Врач
participant ":Clinic" as C
participant "appointment:Appointment" as A
participant ":Patient" as P

Врач -> C ++ : StartAppointment(doctorId, appointmentId)

group Поиск записи и проверка начала приема
  C -> C : OpenAppointment(doctorId, appointmentId)
  note right of C
    Ищет запись по Id в appointments.
    Сверяет appointment.Doctor.Id с doctorId.
  end note
  break Запись не найдена или назначен другой врач
    C --> Врач : KeyNotFoundException / InvalidOperationException
  end
  C --> C : appointment

  break Status != PLANNED или сегодня не день приема
    C --> Врач : InvalidOperationException\nприем нельзя начать
  end

  note right of C
    Из appointments выбирает IN_PROGRESS.
    Проверяет занятость врача, пациента
    и кабинета текущей записи.
  end note
  break У врача, пациента или в кабинете уже идет прием
    C --> Врач : InvalidOperationException\nучастники или кабинет заняты
  end
end

C -> A ++ : Start(currentTime)
note right of A
  Повторно проверяет Status == PLANNED.
  StartedAt = currentTime
  Status = IN_PROGRESS
end note
A --> C --
C --> Врач -- : appointment

group Просмотр истории пациента
  Врач -> P ++ : GetMedicalHistory()
  note right of P
    Выбирает завершенные Appointment.
    Сортирует по StartedAt.
  end note
  P --> Врач -- : история завершенных приемов
end

group Заполнение текущего приема
  Врач -> A ++ : SetExamination(complaints, anamnesis, examination)
  A -> A : EnsureInProgress()
  note right of A
    Изменения разрешены при IN_PROGRESS.
    Жалобы и осмотр не должны быть пустыми.
    Сохраняет Complaints, Anamnesis, Examination.
  end note
  A --> Врач -- : данные осмотра сохранены

  Врач -> A ++ : SetDiagnosis(code)
  A -> A : EnsureInProgress()
  note right of A
    Убирает пробелы по краям,
    переводит код в верхний регистр.
    Проверяет формат МКБ-10
    и сохраняет DiagnosisCode.
  end note
  A --> Врач -- : код диагноза сохранен

  loop для каждого назначения
    Врач -> A ++ : AddPrescription(prescription)
    A -> A : EnsureInProgress()
    note right of A : Проверяет непустой текст и добавляет в prescriptions.
    A --> Врач -- : назначение добавлено
  end
end

group Завершение приема
  Врач -> A ++ : Complete()
  A -> A : EnsureInProgress()
  alt Status != IN_PROGRESS
    A --> Врач : InvalidOperationException\nприем не начат или уже закрыт
  else Не заполнены жалобы, осмотр или код диагноза
    A --> Врач : InvalidOperationException\nне хватает обязательных данных
    note right of A : Прием остается IN_PROGRESS, введенные данные сохраняются.
  else Текущее время раньше StartedAt
    A --> Врач : InvalidOperationException\nневерное время завершения
  else Проверки пройдены
    note right of A
      FinishedAt = текущее время
      Status = COMPLETED
      Прием входит в историю пациента.
      Дальнейшее редактирование запрещено.
    end note
    A --> Врач : прием завершен
  end
  deactivate A
end

@enduml
```

## Операции приема

| Класс | Операция | Что делает |
| --- | --- | --- |
| `Clinic` | `StartAppointment(doctorId, appointmentId)` | Проверяет назначенного врача, статус записи, дату и занятость врача, пациента и кабинета. Начинает прием и возвращает тот же объект `Appointment` |
| `Patient` | `GetMedicalHistory()` | Возвращает завершенные приемы пациента в порядке времени начала |
| `Appointment` | `SetExamination(complaints, anamnesis, examination)` | Заполняет жалобы, анамнез и данные осмотра текущего приема |
| `Appointment` | `SetDiagnosis(code)` | Проверяет формат кода МКБ-10 и сохраняет один диагноз |
| `Appointment` | `AddPrescription(prescription)` | Добавляет назначение |
| `Appointment` | `Complete()` | Проверяет обязательные данные, фиксирует время окончания и статус `COMPLETED`, запрещает дальнейшее редактирование |

`Start(currentTime)` вызывается внутри `Clinic.StartAppointment`. Остальные изменения врач вносит в полученный `Appointment`. Закрытый `EnsureInProgress()` проверяет, что прием идет; его вызывают методы заполнения и завершения.

Блоки `break` прерывают сценарий, если начать прием нельзя. Ветки `alt` показывают результат отдельного вызова `Complete()`. Ошибки передаются как исключения; интерфейс их обработки в прототипе не реализован. На диаграмме заполнение показано для корректных данных: пустой текст, неверный код и неподходящий статус методы также отклоняют исключениями.

УКЭП, исправления подписанных документов, передача СЭМД в ЕГИСЗ и формирование выписки пока не реализованы. `Complete()` завершает прием в прототипе, но не подписывает медицинский документ.
