# Диаграмма последовательности «Запись на прием»

Основной успешный сценарий прецедента [«Запись на прием»](Запись%20на%20прием.md), шаги 1–8, и расширение 7а: слот успели занять, пока пациент подтверждал запись. Поиск по ФИО врача, отмена, перенос и остальные расширения описаны в тексте прецедента.

Пациент вызывает системные операции `:Clinic`. Через портал, приложение, инфомат или медрегистратора вызываются одни и те же операции, поэтому экранов на диаграмме нет. Расписание лежит в `:SlotStorage`: она находит свободные дни и слоты и отдает слот по номеру. Врач (`Doctor`) в записи не участвует. Слот сам знает своего врача и сам себя занимает (`book`).

```plantuml
@startuml booking-sequence
actor Пациент
participant ":Clinic" as C
participant ":DoctorStorage" as DS
participant ":SlotStorage" as SS
participant ":TimeSlot" as Slot
participant ":PatientStorage" as PS
participant ":Patient" as P
participant ":Appointment" as A
participant ":NotificationService" as N

ref over Пациент, C : Идентификация пациента

Пациент -> C ++ : getSpecialties(patientId)
C -> DS ++ : getSpecialties()
DS --> C -- : специальности
C --> Пациент -- : специальности без направления (ПРАВ6)

Пациент -> C ++ : getFreeDates(specialtyId)
note right of C : период: сегодня + 14 дней (ПРАВ8)
C -> SS ++ : getFreeDates(specialtyId, dateFrom, dateTo)
loop для каждого слота специальности в периоде
  SS -> Slot ++ : isFree()
  Slot --> SS -- : да / нет
end
SS --> C -- : дни со свободными слотами
C --> Пациент -- : дни (без свободного времени не показываются)

Пациент -> C ++ : getFreeSlots(specialtyId, date)
C -> SS ++ : findFreeSlots(specialtyId, date)
loop для каждого слота специальности в этот день
  SS -> Slot ++ : isFree()
  Slot --> SS -- : да / нет
end
SS --> C -- : свободные слоты
C --> Пациент -- : свободное время всех врачей специальности

Пациент -> C ++ : selectSlot(patientId, slotId)
C -> SS ++ : getSlot(slotId)
SS --> C -- : slot
C -> Slot ++ : getDoctor()
Slot --> C -- : doctor
C -> PS ++ : getPatient(patientId)
PS --> C -- : patient
C -> P ++ : hasActiveAppointment(doctor.specialty)
P --> C -- : нет (ПРАВ7)
C --> Пациент -- : врач, кабинет, дата и время\nдля подтверждения

Пациент -> C ++ : bookAppointment(patientId, slotId)
C -> SS ++ : getSlot(slotId)
SS --> C -- : slot
C -> PS ++ : getPatient(patientId)
PS --> C -- : patient
C -> Slot ++ : book(patient)
note right of Slot : проверка «свободен?» и занятие\nслота одним действием
opt слот еще свободен
  Slot -> A ** : create(patient, slot)
end
Slot --> C -- : appointment или «занято»
alt слот был свободен
  C -> P ++ : addAppointment(appointment)
  P --> C --
  C -> N ++ : sendConfirmation(appointment)
  N --> C --
  C -> N ++ : scheduleReminder(appointment)
  N --> C --
  C --> Пациент : талон: номер записи, врач,\nкабинет, дата и время
else слот уже занял другой пациент (7а)
  C --> Пациент : время уже занято,\nобновленный список (шаг 4)
end
deactivate C

@enduml
```

## Системные операции

| Шаг сценария | Операция | Что делает |
| --- | --- | --- |
| 1 | включаемый прецедент «Идентификация пациента» | Пациент входит через ЕСИА, ПолиКлик определяет, кто он |
| 2 | `getSpecialties(patientId)` | Берет специальности из хранилища врачей и возвращает те, к которым можно записаться без направления (ПРАВ6) |
| 3 | `getFreeDates(specialtyId)` | Ищет в расписании на 14 дней вперед (ПРАВ8) дни, в которые хотя бы у одного врача специальности есть свободный слот |
| 4 | `getFreeSlots(specialtyId, date)` | Возвращает свободные слоты всех врачей специальности на выбранный день |
| 5 | `selectSlot(patientId, slotId)` | Проверяет, что у пациента нет активной записи к специальности врача этого слота (ПРАВ7), и возвращает врача, кабинет, дату и время для подтверждения |
| 6–8 | `bookAppointment(patientId, slotId)` | Занимает слот, если он еще свободен, создает запись со статусом «запланирована», отправляет подтверждение и планирует напоминание. Если слот уже занят, возвращает «занято» (7а) |
