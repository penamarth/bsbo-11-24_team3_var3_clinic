# Диаграмма последовательности «Запись на прием»

Основной успешный сценарий прецедента [«Запись на прием»](Запись%20на%20прием.md), шаги 1–8, и расширение 7а: слот успели занять, пока пациент подтверждал запись. Отмена, перенос и остальные расширения описаны в тексте прецедента.

```plantuml
@startuml
actor Пациент
participant ":AppointmentService" as S
participant ":Specialty" as Sp
participant ":Schedule" as Sch
participant ":TimeSlot" as Slot
participant ":Appointment" as A
participant ":Patient" as P
participant ":NotificationService" as N

ref over Пациент, S : Идентификация пациента

Пациент -> S ++ : getSpecialties(patientId)
S --> Пациент -- : специальности без направления (ПРАВ6)

Пациент -> S ++ : findFreeSlots(specialtyId, doctorId, dateFrom, dateTo)
note right of S
  по врачу: doctorId задан
  по дате: dateFrom = dateTo
  ближайшее время: весь горизонт
  в 14 дней (ПРАВ8)
end note
S -> Sp ++ : getDoctors()
Sp --> S -- : врачи специальности
loop для каждого врача
  S -> Sch ++ : getFreeSlots(dateFrom, dateTo)
  loop для каждого слота в периоде
    Sch -> Slot ++ : isFree()
    Slot --> Sch -- : да / нет
  end
  Sch --> S -- : свободные слоты врача
end
S --> Пациент -- : свободные слоты\n(врачи и дни без слотов не показываются)

Пациент -> S ++ : selectSlot(patientId, slotId)
S -> P ++ : hasActiveAppointment(specialty)
P --> S -- : нет (ПРАВ7)
S --> Пациент -- : сведения о записи для подтверждения

Пациент -> S ++ : bookAppointment(patientId, slotId)
S -> Slot ++ : book(patient)
note right of Slot
  проверка «свободен ли?» и занятие слота
  выполняются одной неделимой операцией
end note
opt слот еще свободен
  Slot -> A ** : create(patient, slot)
end
Slot --> S -- : appointment или «занято»
alt слот был свободен
  S -> P ++ : addAppointment(appointment)
  P --> S --
  S -> N ++ : sendConfirmation(appointment)
  N --> S --
  S -> N ++ : scheduleReminder(appointment)
  N --> S --
  S --> Пациент : талон: номер записи, врач,\nкабинет, дата и время
else слот уже занял другой пациент (7а)
  S --> Пациент : время уже занято,\nобновленный список слотов (шаг 3)
end
deactivate S

@enduml
```

## Системные операции

| Шаг сценария | Операция | Что делает |
| --- | --- | --- |
| 1 | включаемый прецедент «Идентификация пациента» | Пациент входит через ЕСИА, система определяет, кто он |
| 2 | `getSpecialties(patientId)` | Возвращает специальности, к которым пациент может записаться без направления (ПРАВ6) |
| 3 | `findFreeSlots(specialtyId, doctorId, dateFrom, dateTo)` | Ищет свободные слоты. Способ поиска (по врачу, по дате, ближайшее время) задается параметрами |
| 4–5 | `selectSlot(patientId, slotId)` | Проверяет, что у пациента нет активной записи к этой специальности (ПРАВ7), и возвращает сведения для подтверждения |
| 6–8 | `bookAppointment(patientId, slotId)` | Закрепляет слот, создает запись со статусом «запланирована», отправляет подтверждение и планирует напоминание о приеме |
